# 0053 Local Incident Analysis

## Status

Accepted on 2026-11-18 for the first provider, Ollama. ADR 0054 adds remote providers and separate provider consent.

## Context

PodLord already projects accepted Kubernetes responses into a shared, cache-first resource snapshot. ADR 0036 covers deterministic hints for an inspected detail. The user also wants automatic, concise explanations of changed problems, without asking an AI again for every Pod retry, Event repetition or replica replacement. This adds an outbound model request and a local result cache, so it has a distinct consent and retention boundary.

## Decision

AI settings offer automatic Ollama analysis per imported context. It starts disabled. The inspector offers a separate, explicit analysis action for any selected cached resource, even when no recognized problem code is present or automatic analysis is off. The user chooses an installed model and a reasoning level; PodLord does not infer model quality from file size or silently choose the only installed model. PodLord discovers local models through `/api/tags` and the selected model's chat and thinking capabilities through `/api/show`. Automatic reasoning chooses `medium` only when the model advertises it; otherwise the model decides. The endpoint is fixed to local loopback in the application and cloud-tagged models are excluded. Ollama itself can route cloud models, so operators who require a strict local-only guarantee must also disable Ollama cloud features. Mobile does not expose this local provider.

The runtime, shared by all windows, owns the request queue, throttling, cancellation and cache. It observes accepted resource snapshots and analyzes one recognized problem code per affected resource. A matching Warning Event reason can supply the code or add evidence. The request includes the UI language and screened facts from the bounded relationship graph. Local relationships connect owners, assigned Nodes, mounted claims and volumes, image pull Secrets, affected dependents, Cilium endpoints or nodes, Warning Events and failing resources in the same namespace. Each fact sent to the model has an ID, relationship, resource type and screened status or reason. Known Event message patterns add a fixed hint for authentication, timeout, TLS or missing images without sending the message itself. Names and paths stay local. Free status and Event messages, logs, YAML, credentials and Base64 data remain excluded. Bounded referenced Secret or ConfigMap key names for relevant Pod errors are covered by ADR 0054. Unknown codes yield no automatic AI result and no health assertion. Explicit analysis also uses this graph and states that manual review alone is not evidence of a fault. The existing Kubernetes read schedule is unchanged.

The inspector links, radar highlights and AI evidence resolve relationships from the same accepted resource snapshot. The graph is local. It traverses at most six links, with a 512-resource search bound. Namespace membership is shown in Links but does not connect every resource in that namespace on the map. The AI request prioritizes nearby failures and Warning Events and deduplicates repeated facts. When the selected model advertises a usable context capacity, PodLord budgets the full prompt by conservative UTF-8 size and leaves room for the response. Ollama's theoretical model limit alone does not reveal its allocated runtime context, so PodLord uses an explicit `num_ctx` when available. The ChatGPT model list does not guarantee context metadata. Without a usable capacity, PodLord sends the deduplicated facts from the bounded graph without guessing a model limit. The provider can reject an oversized request, while a local runtime may truncate it. A separate bounded sample of other failing resources in the same namespace helps identify shared incidents. The cache key hashes context, namespace, topmost known workload owner, problem code, screened graph facts, provider and account or credential identity, model, reasoning, language and prompt version. It excludes resource names, Pod and replica UIDs, timestamps and raw retry counts. Replicas with the same problem reuse an answer; changed evidence gets a new key. The private profile's `incident-ai.json` retains at most 500 answers for 90 days, provider-specific consent and model choices. It stores answers and opaque hashes, not request payloads or Kubernetes free text. Deleting it resets consent and answers. Disabling automatic analysis cancels its requests. Explicit analysis remains available and does not enable automatic transmission.

One model request runs at a time. Automatic requests are separated by at least 30 seconds and limited to five per hour per context. The queue holds at most 32 pending distinct incidents. A failure pauses automatic requests for 15 minutes. An explicit **Analyze** or **Analyze again** action replaces the inspected answer and bypasses those passive limits, while retaining single-flight behavior. The UI only reads in-memory results. The prompt requests short explanations in the selected UI language for a junior without cluster context and avoids semicolons and long dashes as sentence separators. Model output must parse as three short JSON fields; invalid output is shown as a failure. The inspector shows those fields, loading and recovery state. For an analyzed local resource it also builds a copyable, read-only `kubectl describe` command from the selected kubeconfig, context and resource. The command stays local and PodLord never runs it or requires `kubectl` to analyze. Read-only informational text is selectable.

## Consequences

This slice explains recognized incidents but cannot determine an unobserved root cause. A Secret seen among available resources does not prove the kubelet can use it. A Secret not seen there does not prove it is missing. An image pull failure alone does not identify registry reachability, image availability, network failure or authentication failure. The automatic payload intentionally excludes the free Event message even when it might explain the cause. The prompt requires a concrete unknown and an evidence gathering next step where necessary. It describes incomplete observations without mentioning PodLord's storage mechanism. The model may still give a wrong suggestion. ADR 0054 describes remote provider boundaries. No general plugin framework is introduced.
