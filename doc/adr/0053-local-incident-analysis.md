# 0053 Local Incident Analysis

## Status

Accepted on 2026-11-18 for the first provider, Ollama. ADR 0054 adds remote providers and separate provider consent.

## Context

PodLord already projects accepted Kubernetes responses into a shared, cache-first resource snapshot. ADR 0036 covers deterministic hints for an inspected detail. The user also wants automatic, concise explanations of changed problems, without asking an AI again for every Pod retry, Event repetition or replica replacement. This adds an outbound model request and a local result cache, so it has a distinct consent and retention boundary.

## Decision

AI settings offer automatic Ollama analysis per imported context. It starts disabled. The inspector offers a separate, explicit analysis action for any selected cached resource, even when no recognized problem code is present or automatic analysis is off. The user chooses an installed model and a reasoning level; PodLord does not infer model quality from file size or silently choose the only installed model. PodLord discovers local models through `/api/tags` and the selected model's chat and thinking capabilities through `/api/show`. Automatic reasoning chooses `medium` only when the model advertises it; otherwise the model decides. The endpoint is fixed to local loopback in the application and cloud-tagged models are excluded. Ollama itself can route cloud models, so operators who require a strict local-only guarantee must also disable Ollama cloud features. Mobile does not expose this local provider.

The runtime, shared by all windows, owns the request queue, throttling, cancellation and cache. It observes accepted resource snapshots and analyzes warning or critical resources. A recognized problem code or matching Warning Event reason identifies a specific failure. Other unhealthy resources use their observed health as the trigger. Large snapshots are screened in a background job. A newer observation or closed context invalidates an unfinished job before it can update the AI view or send a request. The request is one JSON object with UI language, selected resource identity, problem code, bounded cluster observations and a `resources` array. Each resource has its real type, name and namespace, relationship and screened facts. `linkedResource` identifies the observed parent by its real identity. Internal aliases stay local. Valid Kubernetes UUIDs are sent when available so an Event and its subject can be distinguished, while resource API paths remain local. A matching Event field path identifies the real Pod container name when verified. The model cites real resource identities. PodLord converts known names to local references for cache reuse and clickable links in the inspector. Local relationships connect owners, assigned Nodes, mounted claims and volumes, image pull Secrets, affected dependents, Cilium endpoints or nodes, Warning Events and failing resources in the same namespace. Warning Event messages, container-state messages and condition messages are sent after best-effort redaction. Available creation and Event times, container names and image references, per-container states, conditions, Pod QoS, limits, Event action, container image-pull policy, Secret type and the presence of a registry auth data key add context without sending its value. Known Event message patterns remain local and are not sent as diagnosis hints. Known names and common path patterns are screened in free-text messages. Full logs, YAML, credentials and Secret data fields remain excluded. Arbitrary messages can still contain sensitive text or encoded values. Bounded referenced Secret or ConfigMap key names for relevant Pod errors are covered by ADR 0054. Unknown codes yield no automatic AI result and no health assertion. Explicit analysis also uses this graph and states that manual review alone is not evidence of a fault. The existing Kubernetes read schedule is unchanged.

The inspector links, radar highlights and AI evidence resolve relationships from the same accepted resource snapshot. The graph is local. It traverses at most six links, with a 512-resource search bound. Namespace membership is shown in Links but does not connect every resource in that namespace on the map. The AI request prioritizes nearby failures and Warning Events and deduplicates repeated facts. When the selected model advertises a usable context capacity, PodLord budgets the full prompt by conservative UTF-8 size and leaves room for the response. Ollama's theoretical model limit alone does not reveal its allocated runtime context, so PodLord uses an explicit `num_ctx` when available. The ChatGPT model list does not guarantee context metadata. Without a usable capacity, PodLord sends the deduplicated facts from the bounded graph without guessing a model limit. The provider can reject an oversized request, while a local runtime may truncate it. A separate bounded sample of other failing resources in the same namespace helps identify shared incidents. The automatic cache key hashes context, namespace, topmost known workload owner, problem code, screened graph facts, provider and account or credential identity, model, reasoning, language and prompt version. It excludes individual Pod names, Kubernetes UIDs, timestamps and raw retry counts, so replicas with the same problem reuse an answer. Explicit analysis is specific to the selected resource. Changed evidence gets a new key. The private profile's `incident-ai.json` retains at most 500 answers for 90 days, provider-specific consent and model choices. It stores model answers and opaque hashes, not request payloads. A model can still quote cluster text in an answer. Deleting it resets consent and answers. Version 4 clears automatic opt-ins saved by older request versions before names and images were shared. Models, accounts and answer records stay available. Disabling automatic analysis cancels its requests. Explicit analysis remains available and does not enable automatic transmission.

One model request runs at a time. Automatic requests are separated by at least 30 seconds and limited to five per hour per context. The queue holds at most 32 pending distinct incidents. A failure pauses automatic requests for 15 minutes. An explicit **Analyze** or **Analyze again** action replaces the inspected answer and bypasses those passive limits, while retaining single-flight behavior. The UI only reads in-memory results. The prompt requests short explanations in the selected UI language for a junior without cluster context and avoids semicolons and long dashes as sentence separators. Model output must parse as three short JSON fields. The prompt asks for real resource identities. The inspector shows the fields, loading and recovery state, and links known cited names inside the answer. Raw Kubernetes UIDs and observed resource names echoed by a model are replaced with internal local references before an answer is cached. The AI tab defaults to Response and can show a Request preview of the current model input. It keeps the last completed answer visible through temporary empty results for the same resource and model, then clears it if analysis fails or the inspected scope changes. A successful answer for the visible AI tab plays the bundled completion sound at the alert volume unless muted. For an analyzed local resource PodLord builds a copyable, read-only `kubectl describe` command from the selected kubeconfig, context and resource. The command stays local and PodLord never runs it or requires `kubectl` to analyze. Read-only informational text is selectable.

## Consequences

This slice explains recognized incidents but cannot determine an unobserved root cause. A Secret seen among available resources does not prove the kubelet can use it. A Secret not seen there does not prove it is missing. Best-effort message redaction cannot guarantee removal of every sensitive value in arbitrary controller text. A selected cloud provider can receive residual private text. The model treats messages as untrusted data and is asked not to echo identifiers. The prompt requires a concrete unknown and an evidence gathering next step where necessary. It describes incomplete observations without mentioning PodLord's storage mechanism. The model may still give a wrong suggestion. ADR 0054 describes remote provider boundaries. No general plugin framework is introduced.
