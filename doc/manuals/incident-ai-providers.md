# Incident analysis providers

The native desktop PodLord app explains recognized Kubernetes problems using Ollama, a ChatGPT subscription, Claude API or OpenRouter. In **Settings → AI**, use the green **+** beside **Model** to connect a provider. The list then shows actual models under each connected provider's heading. Choosing a model selects its provider. The **+** never changes the selected model. All connected accounts stay visible below the model list, with the number of analysis requests sent in the last 24 hours. Model lists load at startup and after connection, then refresh in the background when AI settings or the analysis panel reopens after 15 minutes. Open a resource's **AI** Inspector tab and switch on **Auto** for that imported context and provider. The circular arrow requests a fresh answer for the current problem. The Inspector links to AI settings if no model is selected. Hover over or focus an icon for its action name.

PodLord never selects a model automatically. Switching providers preserves each provider's model. Signing out clears that provider's selected model. A different provider needs its own context opt-in before automatic analysis. The request includes the UI language, observed problem and a bounded graph of up to 24 related facts. It follows the resource's owners, assigned Node, referenced claims and volumes, image pull Secret presence, affected dependents, matching Cilium endpoint or node, Warning Events and other failing resources in the namespace. Each fact has a short ID, relationship, type and screened status. Known Event message patterns add a fixed hint for authentication, timeout, TLS or missing images without sending the message itself. PodLord keeps resource names and paths locally so the AI tab can open cited evidence in the inspector. It never sends logs, free Event messages, resource names, image addresses, Secret names, Secret values or Base64 data. For relevant Pod errors, it may send screened Secret or ConfigMap key names. A Secret seen in the cache is no proof that the kubelet can use it. The answer cache lasts up to 90 days. Repeated Pods, Events and retries of the same problem reuse an answer; changed evidence triggers a new one.

## Ollama

Start Ollama locally, install a chat model with `ollama pull <model>`, then select it. PodLord connects only to `127.0.0.1:11434` and excludes models tagged `:cloud`. For strict local operation, set `disable_ollama_cloud` to `true` in `~/.ollama/server.json` and restart Ollama. See the [Ollama FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.mdx#how-do-i-disable-ollama-cloud-features).

## ChatGPT subscription

Press **+ → ChatGPT** and approve PodLord in the system browser, then choose a model from the loaded catalog. PodLord keeps one ChatGPT account at a time. The sign-out icon beside the account removes it before another account can connect. If plan permission was denied, choose **+ → ChatGPT** again. PodLord does not read Zed, Codex or another application's tokens. Direct app use must be allowed by the ChatGPT plan. Review app access in [ChatGPT Settings](https://chatgpt.com/settings). See OpenAI's [sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [models](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) and [account management](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) documentation.

## Claude API

Create a workspace-scoped API key in the Claude Console, press **+ → Claude API**, paste the key and press Enter or the save icon. Choose a model when the catalog loads. A Claude web or Claude Code subscription does not supply this key or pay for API usage. If the catalog is unavailable, check key scope and access in the [Claude API overview](https://platform.claude.com/docs/en/api/overview) and [model-list reference](https://platform.claude.com/docs/en/api/models/list). PodLord calls the [Messages API](https://platform.claude.com/docs/en/api/messages/create) with version `2026-10-21`.

## OpenRouter

Press **+ → OpenRouter** and finish sign-in in the system browser. OpenRouter issues an API key to PodLord using a local callback and PKCE. Select a text model when the catalog loads. PodLord keeps one OpenRouter connection at a time; the sign-out icon removes its key. OpenRouter uses its own credits and billing. PodLord reads its current [model catalog](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) and calls [Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request). Check the [OpenRouter OAuth guide](https://openrouter.ai/docs/guides/overview/auth/oauth) if browser sign-in fails. PodLord does not invoke an automatic model selector unless you explicitly choose that catalog entry.

## Credentials and cache

The selected profile contains `incident-ai.json` for provider, models, consent, cached answers and hashed account request timestamps. Request counts cover a rolling 24 hours and include only actual analysis calls, not login or model catalog refreshes. Credentials are stored in macOS Keychain, Windows Credential Manager or the Linux Secret Service. PodLord reads them automatically under your OS account. If the password store is unavailable or locked, cloud providers stop with an error; PodLord does not fall back to plaintext files. Existing owner-only `chatgpt-auth.json`, `claude-auth.json` and `openrouter-auth.json` files are migrated on first launch and deleted after a successful transfer. Migration keeps the active ChatGPT account. The sign-out icon clears local credentials. ChatGPT sign-out also attempts remote revocation. If remote revocation cannot be confirmed, disconnect PodLord in ChatGPT settings. Remove `incident-ai.json` while PodLord is closed to erase cached answers and automatic opt-ins. The cache stores model answers and opaque hashes, not Kubernetes free text.

If credential access fails, unlock your macOS login keychain or check that Windows Credential Manager is available under your signed-in account. On Linux, start and unlock a Secret Service implementation such as GNOME Keyring in your desktop session. If migration fails, close other PodLord instances and check that the old file is readable only by its owner. PodLord leaves that file in place until transfer succeeds.

Open a cited resource or Event directly from the AI tab to check the model's claim. Under **Next check**, copy the read-only `kubectl describe` command if you want to inspect the selected resource in a terminal. It uses the selected kubeconfig and context. PodLord does not run it and analysis does not require `kubectl`.
