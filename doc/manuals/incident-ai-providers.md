# Incident analysis providers

The native desktop PodLord app explains recognized Kubernetes problems using Ollama, a ChatGPT subscription, Claude API or OpenRouter. In **Settings → AI**, use the green **+** beside **Model** to connect a provider. The list then shows actual models under each connected provider's heading. Choosing a model selects its provider. The **+** never changes the selected model. All connected accounts stay visible below the model list, with the number of analysis requests sent in the last 24 hours. Model lists load at startup and after connection, then refresh in the background when AI settings or the analysis panel reopens after 15 minutes. In **Settings → AI**, enable **Auto** for an imported context and provider. The inspector shows an AI tab only when a cloud account is connected or an installed Ollama model is selected. The circular arrow requests a fresh answer for the current problem. The Inspector links to AI settings if no model is selected. Hover over or focus an icon for its action name.

PodLord never selects a model automatically. Switching providers preserves each provider's model. Signing out clears that provider's selected model. A different provider needs its own context opt-in before automatic analysis. The request is structured JSON with the UI language, observed problem and separate resources from the bounded graph, sized to the model context when known. Each resource has its real type, name, namespace, relationship and status. `linkedResource` identifies an observed graph connection. Internal reference numbers are not sent to the model. A Kubernetes UID is included when it has the expected UUID form. Creation and Event times, container names and image references, per-container state and image-pull policy, conditions, Pod QoS, rollout, storage, Secret type and registry auth key presence can help the diagnosis. Available Pod and Node CPU and memory usage is sent with its measurement time, completeness and staleness, alongside known requests, limits or capacity. PodLord does not have observed I/O or storage occupancy to send. The graph follows owners, assigned Nodes, claims and volumes, Secret references, dependents, matching Cilium resources, Warning Events and other failing resources in the namespace. Warning Event, container-state and condition messages go to the selected model after best-effort redaction of known names, addresses and common credential patterns. Arbitrary messages may still contain private information that these patterns miss. The model does not receive full logs, YAML, kubeconfigs or Secret values. Relevant Pod errors may include screened Secret or ConfigMap key names. Seeing a Secret in the cache does not prove the kubelet can use it. In the inspector, **Response** shows the report by default and **Request** shows the model instructions and structured user content for the current snapshot. Authentication headers are omitted. Answers are cached for up to 90 days. Repeated Events and retries reuse an answer when the meaningful evidence stays the same; a manual refresh requests a new one.

## Ollama

Start Ollama locally, install a chat model with `ollama pull <model>`, then select it. PodLord connects only to `127.0.0.1:11434` and excludes models tagged `:cloud`. For strict local operation, set `disable_ollama_cloud` to `true` in `~/.ollama/server.json` and restart Ollama. See the [Ollama FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.mdx#how-do-i-disable-ollama-cloud-features).

## ChatGPT subscription

Press **+ → ChatGPT** and approve PodLord in the system browser, then choose a model from the loaded catalog. PodLord keeps one ChatGPT account at a time. The sign-out icon beside the account removes it before another account can connect. If plan permission was denied, choose **+ → ChatGPT** again. PodLord does not read Zed, Codex or another application's tokens. Direct app use must be allowed by the ChatGPT plan. Review app access in [ChatGPT Settings](https://chatgpt.com/settings). See OpenAI's [sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [models](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) and [account management](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) documentation.

## Claude API

Create a workspace-scoped API key in the Claude Console, press **+ → Claude API**, paste the key and press Enter or the save icon. Choose a model when the catalog loads. A Claude web or Claude Code subscription does not supply this key or pay for API usage. If the catalog is unavailable, check key scope and access in the [Claude API overview](https://platform.claude.com/docs/en/api/overview) and [model-list reference](https://platform.claude.com/docs/en/api/models/list). PodLord calls the [Messages API](https://platform.claude.com/docs/en/api/messages/create) with version `2026-10-21`.

## OpenRouter

Press **+ → OpenRouter** and finish sign-in in the system browser. OpenRouter issues an API key to PodLord using a local callback and PKCE. Select a text model when the catalog loads. PodLord keeps one OpenRouter connection at a time; the sign-out icon removes its key. OpenRouter uses its own credits and billing. PodLord reads its current [model catalog](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) and calls [Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request). Check the [OpenRouter OAuth guide](https://openrouter.ai/docs/guides/overview/auth/oauth) if browser sign-in fails. PodLord does not invoke an automatic model selector unless you explicitly choose that catalog entry.

## Credentials and cache

The selected profile contains `incident-ai.json` for provider, models, consent, cached answers and hashed account request timestamps. When upgrading a profile saved before request version 4, PodLord clears automatic AI opt-ins because names and image references are now sent. Choose Auto again per context if you want automatic analysis. Selected models, connected accounts and cached answers remain. Request counts cover a rolling 24 hours and include only actual analysis calls, not login or model catalog refreshes. Credentials are stored in macOS Keychain, Windows Credential Manager or the Linux Secret Service. PodLord reads them automatically under your OS account. If the password store is unavailable or locked, cloud providers stop with an error; PodLord does not fall back to plaintext files. Existing owner-only `chatgpt-auth.json`, `claude-auth.json` and `openrouter-auth.json` files are migrated on first launch and deleted after a successful transfer. Migration keeps the active ChatGPT account. The sign-out icon clears local credentials. ChatGPT sign-out also attempts remote revocation. If remote revocation cannot be confirmed, disconnect PodLord in ChatGPT settings. Remove `incident-ai.json` while PodLord is closed to erase cached answers and automatic opt-ins. The cache stores model answers and opaque hashes, not raw request payloads. A model can still quote cluster text in its answer.

If credential access fails, unlock your macOS login keychain or check that Windows Credential Manager is available under your signed-in account. On Linux, start and unlock a Secret Service implementation such as GNOME Keyring in your desktop session. If migration fails, close other PodLord instances and check that the old file is readable only by its owner. PodLord leaves that file in place until transfer succeeds.

Click a known resource name in the AI answer to inspect it. **Next check** shows a copyable, read-only `kubectl describe` command for the selected kubeconfig and context. PodLord does not run it and analysis does not require `kubectl`.
